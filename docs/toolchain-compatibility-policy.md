# Toolchain Compatibility & Version Support Policy

This document establishes the official support matrix, deprecation schedules, and testing policies for all development and execution toolchains used in StellPoker.

## 2. Component Support Policies

### 2.1 Noir (`nargo`) and Circuit Artifacts
- **Proving System:** UltraHonk (Barretenberg backend).
- **Matrix Window:** StellPoker guarantees backward and forward compatibility across the current pinned release and ±1 adjacent release.
- **Circuit Verification:** Whenever circuits in `circuits/` are modified or a new `nargo` version is adopted:
  - Gate counts and constraint limits must be re-verified using `nargo info`.
  - ACIR bytecode compatibility with TACEO `co-noir` must be validated.
  - Test vectors generated by `stellpoker-test-vectors` must match across all matrix versions.

### 2.2 Soroban Smart Contracts & Rust
- **Compilation Targets:**
  - Primary target: `wasm32-unknown-unknown`
  - Host function requirements: Native BN254 host functions introduced in Protocol 25 and extended in Protocol 26.
- **Cargo MSRV (Minimum Supported Rust Version):** The MSRV is tested in CI to prevent accidental usage of unreleased or nightly-only language features in production contracts.

### 2.3 Frontend & Node.js
- **Framework:** Next.js 15, React 19, TypeScript 5.
- **Node.js Policy:**
  - Only active and maintenance LTS versions of Node.js (`18`, `20`, `22`, `24`) are officially supported.
  - End-of-Life (EOL) Node releases are dropped from the matrix immediately upon official EOL announcement.

## 3. Version Upgrade & Deprecation Process

1. **Matrix Prototyping:** New toolchain versions are first added to `.github/workflows/compatibility-matrix.yml` as experimental or matrix entries.
2. **Impact Assessment:**
   - Contract size and gas budgets must remain within limits (`scripts/check_soroban_budgets.py`).
   - Circuit constraints must not regress (`scripts/circuit_constraints.py`).
3. **Promotion:** Once all matrix jobs pass consistently over two consecutive weekly runs without flakiness:
   - The version in `README.md` and `flake.nix` is updated.
   - Pinned dependencies in `Cargo.toml` and `package.json` are bumped.
4. **Deprecation Notice:** When a toolchain version is slated for removal, a notice is added to this policy document at least 30 days prior to dropping CI testing.

---

## 4. Continuous Integration

The cross-version compatibility matrix is tested automatically:
- On every push and pull request touching toolchain files (`Cargo.toml`, `package.json`, `Nargo.toml`, workflows).
- On a scheduled weekly cron run (Mondays at 06:00 UTC) via `.github/workflows/compatibility-matrix.yml`.
